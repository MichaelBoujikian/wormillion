## Netlify note for the lead (outside the sweep's scope; from docs.netlify.com behaviour, not verified live)

Netlify builds once per **push / deploy trigger**, not once per commit: fast-forwarding or merging 105 commits to `main` in one push produces one build (and auto-deploy is locked anyway, so the release is one "Trigger deploy"). GitHub Pages likewise deploys once per push. A true merge commit (`git merge --no-ff expansion`) keeps the 105 commits in history and is still one push; `git merge --squash` makes main's history one commit but loses the per-chunk log the HANDOFF relies on - either way Netlify counts one deploy.
